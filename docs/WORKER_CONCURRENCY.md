# Worker 平行配音

`Narration:MaximumConcurrentJobs` 控制每個 Worker process 同時處理的工作數，允許 1～4，
預設為 1。Docker Compose 可在 `.env` 設定：

```dotenv
NARRATION_MAX_CONCURRENT_JOBS=2
```

重新啟動 Worker 才會套用。沒有修改既有正式環境設定；單 GPU 的 BlueMagpie 環境先保留 1，
它的 gateway 仍有 GPU 互斥鎖，增加配音工作數不代表同一 GPU 能平行生成。
提高工作數前，需確認記憶體、音訊暫存空間與 provider 的同時呼叫限制足夠。

排程器只在有空位時領取工作，不預先占用等待中的工作租約。領取與過期租約回收共用
單一循環，每份已領取工作則各自使用資料庫 scope、租約、暫存檔與取消／逾時控制。
一份完成便可補上下一份，另一份失敗不會中止整個 Worker。

Worker 停止時會通知所有執行中的工作並等待收尾。各 provider 仍沿用既有恢復規則：
BlueMagpie 可在 cooldown 後重試，其他工作可能等待租約到期後處理；VoAI 不會因此開啟
自動付費重播。完整批次仍須全部完成後由使用者啟用，平行處理不會逐冊切換目前音訊。

這個設定控制**不同配音工作之間**的平行處理；Edge 與 VoAI 多角色工作另有下方的片段設定，
BlueMagpie 與 3wa 的單工作片段仍依序生成。
此上限不是跨 replica 的總額度，也不是使用者公平排程或計費 hard quota。

測試使用真實 PostgreSQL 與合成測試 provider，驗證兩份工作同時執行、第三份等待空位、
租約／音檔互不共用，以及停止後的新 Worker 透過過期租約完成剩餘工作。
這些測試沒有呼叫外部 TTS 或 GPU，也不表示某個 provider 在 2～4 份工作下已通過壓力驗收。

## Edge 多角色工作的片段平行

`EdgeTts:MaximumConcurrentChunks` 控制每份 Edge 多角色配音工作內的同時處理片段數，
允許 1～4，預設 1。Compose 對應：

```dotenv
EDGE_TTS_MAX_CONCURRENT_CHUNKS=2
```

同樣需重新啟動 Worker 才會套用。工作數與片段數分開控制；例如兩份 Edge 工作、每份兩段，
每個 process 最多有四段同時處理。此值不限制跨 replica 總量，也不影響 BlueMagpie、VoAI、
3wa 或舊版單聲線工作。預設與既有環境仍維持一次一段，沒有對正式服務提高呼叫量。

片段可能先後完成，但音訊組合仍按原 turn／chunk 順序，停頓只插在原本的位置。
時間軸使用各片段與停頓音訊的 ffprobe 實測時長；進度回報是已完成片段數，不是劇本位置。
同一流程內只有失敗片段會重試，等待重試時仍占用原空位；Edge 沒有跨工作嘗試的片段快取。

任一片段用完重試次數、探測失敗或整個工作取消時，停止領取新片段、取消並等待所有
執行中的片段收尾，之後才清除暫存目錄。ffmpeg／ffprobe 子程序在取消時也會終止並等待
輸出管線結束。只有全部成功、組合與驗證完成後才以原子替換發布候選成品。

測試以受控的完成順序驗證上限、後段先完成、時間軸與音訊順序、單段重試、失敗、取消及
保留既有輸出，另以本機真實 FFmpeg 合成無聲音訊驗證組合。這不代表外部 Edge 服務的
限流、實際品質或平行效能已驗收。

## VoAI 多角色工作的片段平行

`VoAi:MaximumConcurrentChunks` 控制每份 VoAI 工作同時處理的片段數，允許 1～4，預設 1。
Compose 對應 `VOAI_MAX_CONCURRENT_CHUNKS`，修改後須重新啟動 Worker。工作數與片段數相乘：
兩份 VoAI 工作各設 2 段，該 Worker 最多可同時送出 4 個要求；多個 replica 需另行計算。
啟用付費服務仍須獨立的 `VOAI_PAID_API_KEY`，本次沒有填入金鑰、提高正式設定或呼叫 VoAI。

所有 turn 的聲線與合成參數先驗證，通過後才開始請求。只建立設定數量的執行槽，有空位
才處理下一片；各段有獨立 WAV 檔案，最後依原文順序交給既有 FFmpeg composer，保留
原 turn 的音量、停頓與時間軸。進度表示完成片段數，回報不會重疊或倒退。

任一請求或進度回報失敗，會取消其他片段，等所有請求與檔案關閉後才清理暫存目錄。
只有整份成功才組合音訊。既有的單要求 timeout／response bytes 上限、總片段數與
工作音訊預算仍有效；總音訊預算在每片完成後累加檢查，超出即失敗、不發布成品。
這不是即時磁碟配額：正在下載的片段尚未計入總數，暫存空間須另留最多並行片段數乘以
單回應上限的餘裕。也不是供應商計費額度，取消要求不保證供應商沒有執行或收費。

VoAI 保留失敗與逾時不自動重播的規則，Worker 重啟後也不接續已過期的 VoAI 租約；
本次沒有加入付費片段重試或快取恢復。提高並行數前需另行確認帳號允許的同時要求數。

新增測試使用受控 client，驗證預設依序、2～4 段上限、後段先完成與空位補入、組合順序、
參數、依序回報進度、共用預算、失敗取消與等待檔案收尾。完整 677 項單元測試通過，
其中 42 項涵蓋 VoAI provider／HTTP client；沒有以替身回應冒充實際 VoAI 品質或速度驗收。
