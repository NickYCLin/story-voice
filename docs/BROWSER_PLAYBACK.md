# 瀏覽器播放驗證

播放器的 DOM 測試會模擬媒體事件，因此另外以正式前端建置、瀏覽器實際解碼的音檔，
檢查播放與跳轉。2026-09-08 這次驗證使用 Windows、本機 HTTP 服務、合成書目與
FFmpeg 產生的 120 秒低音量測試音；沒有使用私人正文、聲音樣本或正式帳號。

## 測試範圍

| 瀏覽器 | 音檔 | 環境 |
|---|---|---|
| Chrome 152.0.7977.83 | MP3、PCM WAV | Playwright 的 `chrome` channel |
| Firefox 155.0 | MP3、PCM WAV | Playwright Firefox build |
| WebKit 26.5 | MP3、PCM WAV | Playwright Windows WebKit build |

書庫、時間軸、登入與進度 API 使用固定測試回應；音檔由真正的 HTTP 服務提供，包含
Range 回應。這驗證前端與瀏覽器的整合，不取代正式 API 權限、跨裝置同步或部署驗收。

每種音檔都檢查：

1. 讀到音訊長度後，從已存的 42 秒位置續播，確認媒體時間確實前進，再暫停。
2. 切換至 60 秒的第二章，確認章節、角色與文字跟著變更。
3. 以方向鍵調整播放進度，切換 1.5 倍速，以及靜音／取消靜音。
4. 重新整理後讀回約 60 秒的位置並續播。
5. 快速跳到音檔尾端、往回調整，再按播放；確認從指定位置播完，重新開啟後不再顯示舊續播提示。
6. 在 1440、390、320px 視窗下確認播放器沒有內部水平溢位，並檢查截圖。

測試的進度 API 會核對每次 PUT 的版本與 CSRF header。正式 API 與資料庫的 owner、
版本衝突等檢查另有後端測試。瀏覽器截圖與產生的音檔留在 Git 忽略的測試輸出中。

## 這次修正

書籍詳細欄會縮窄播放器；Firefox 原本可能讓章節按鈕超出卡片。控制列現在允許換行，
倍速標籤與選項分開排列，保留原有的按鈕最小觸控範圍。

這次 Firefox 對測試 WAV 跳到最後位置時發生解碼錯誤；使用者往回調整再按播放，原本
的重試會呼叫 `load()` 並丟掉選定位置。現在重試會先重新讀取 metadata、恢復位置並等
跳轉完成，再播放；metadata 或跳轉各自等候超過 10 秒、或音檔仍失敗時，會提供重試
提示。連按播放不會重複送出要求，離開播放器會取消等待，避免稍後誤播。這不修復瀏覽器的解碼器。
DOM 測試另涵蓋重載後恢復位置、舊 seeked 事件、取消、連按播放與逾時後重試。

## 尚待驗收

這次 Windows WebKit 對 24 kHz、48 kbit/s 測試 MP3 顯示約 118.11 秒，Chrome 與 Firefox
顯示約 120 秒；相同來源的 PCM WAV 為 120 秒。播放控制與結束流程可運作，但不能據此
宣稱所有平台的 MP3 長度與時間軸都完全一致，仍須以目標平台和實際成品確認。

## 斷線後的進度同步

2026-09-08 補驗暫停中的播放器：網路中斷時跳到 60 秒，確認出現未同步提示；恢復連線後不用繼續播放，就會保存最後位置。另在離線期間由測試伺服器將遠端位置更新至 90 秒，重連後回 409，播放器停止後續同步，沒有覆寫遠端位置。

保存失敗會保留目前工作的最後待送位置，較新的跳轉或播完位置優先。瀏覽器 `online` 事件會觸發一次重試；若事件到達時仍在等前一個請求，則在該請求結束後重試一次，不啟動循環重送。重新連線不會自動播放音訊。離開工作後移除事件監聽，切換工作也不會短暫顯示前一個工作的遠端進度。

這份待送資料只存在目前播放器的記憶體中；離線關閉頁面後仍以既有本機續播標記為備援，不宣稱關閉頁面後可以背景補送。若伺服器已保存但回應遺失，後續原版本重試可能回 409；程式會保留這項衝突保護，不擅自取得新版本後覆寫。`online` 事件也不保證伺服器已恢復，失敗時仍顯示未同步提示。

Windows Chrome 152、Playwright Firefox 155 與 WebKit 26.5 均通過上述情境，67 項前端執行測試與 164 項靜態檢查也通過。驗證使用 `/StoryVoice/` 正式建置、合成 WAV、本機 HTTP 進度伺服器與瀏覽器的離線切換；進度 GET／PUT 經過真正的 HTTP，沒有用 route fulfill 繞過斷線。這不等同真實行動網路、音訊串流中斷或正式帳號同步驗收。

## 音訊資料延遲

2026-09-08 以 HTTP 服務先送出少量 WAV 資料、暫停剩餘回應，重現瀏覽器已發出 `waiting`、畫面卻仍顯示「正在播放」的問題。播放器現在顯示「等待音訊載入…」，使用者仍可暫停；收到 `playing` 後才清除等待提示。單純下載停滯的 `stalled` 事件不代表播放已中斷，因此不切換提示。

Chrome 152、Firefox 155、WebKit 26.5 均通過兩種操作：等待期間按暫停，資料恢復後維持暫停；保留播放要求時，資料恢復後正常播放。1440／390／320px 下的提示與控制列沒有水平溢位。測試使用不同音檔 URL 避免重用已緩存的媒體，並延遲 Range 回應；書目與帳號仍是合成資料。69 項前端互動測試與 164 項靜態檢查通過，DOM 測試另涵蓋錯誤、切換音檔及暫停後晚到的播放事件。

這次涵蓋音訊起始資料延遲，不代表已驗證播放途中反覆斷線、長時間串流或實際行動網路。

真正的 macOS Safari、iPhone／iPad、Android，以及鎖屏、背景播放、耳機控制、系統音量、
長時間串流與弱網路仍未完成驗收。Playwright WebKit 是獨立的測試 build，影音支援也受
作業系統影響；詳見 [Playwright 的瀏覽器說明](https://playwright.dev/docs/browsers#webkit)。
